Common mistakes on widget app zh-Hans listings

  • Translating only the description — name, subtitle, and keywords still English while widget screenshots dominate the gallery
  • Pasting 小组件 into every keyword slot — crowding the 100-character field without room for your app’s actual use case (habit, weather, finance)
  • English widget titles in PNG exports — Connect caption fields are zh-Hans but burned-in sample widget names on the image file are still Latin
  • Assuming widget UI localization = listing done — runtime widget strings can be Chinese while the App Store row still falls back to English
  • What's New still English after widget launch — see What's New in Simplified Chinese when the widget feature shipped in a recent version
  • Generic utility copy — description written for the main app with one sentence mentioning widgets instead of naming Home vs Lock Screen workflows
  • ChatGPT 翻译腔 on Lock Screen jargon — literal translations of “complication” or “StandBy” that native readers do not use in App Store copy

What good zh-Hans widget listing copy looks like

Listing fields should name the widget surfaces you actually ship — aligned with your screenshot order:

  • Subtitle — one concrete promise: “锁屏与桌面小组件” or “待办桌面组件，一目了然” — not vague “提升效率”
  • Keywords — mix category terms (待办, 天气, 习惯) with widget intent (小组件, 锁屏) within Connect’s ~100-character zh-Hans budget; see Simplified Chinese keywords guide
  • Description — short paragraphs for Home Screen sizes, Lock Screen slots, and StandBy if you market it — mirror screenshot sequence
  • Screenshot captions on widget frames — name the on-screen action: “长按桌面添加小组件” not “强大功能”
  • Sample widget titles in caption lines — when your gallery shows example data, caption sheet lists zh-Hans equivalents for designer re-export
  • Voice consistency — same 你/您 choice as your description across overlay lines and promotional text
