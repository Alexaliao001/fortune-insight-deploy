EventKit integration vs zh-Hans listing copy — two different jobs

Teams assume shipping Calendar save in the app covers storefront language. Connect and iOS actually separate in-app event behavior from product-page copy:

  • EventKit / EKEventStore — your app creates or updates EKEvent records the user saves to Calendar. Controls in-app save sheets and permission prompts — not App Store language. AppLocale does not implement this.
  • Add to Calendar / Save event UI — in-app buttons and system sheets when users confirm an event. Localizing runtime UI requires Xcode string catalogs — outside AppLocale scope unless you bundle those strings in your listing brief as reference only.
  • Remind me / alerts copy — notification or reminder toggles tied to saved events may appear in screenshots. Listing caption lines describe buyer value — not alarm scheduling code.
  • Pricing and Availability → China — makes the app downloadable on the China App Store. Separate from language rows.
  • App Store tab → Chinese (Simplified) localization — independent row for title, subtitle, keywords, description, promotional text, screenshots, and caption lines. Empty or English here means China buyers see English fallback regardless of Calendar integration.

A compliant US listing with Add to Calendar enabled and a localized China listing are both required when you sell on the China storefront — neither replaces the other.
