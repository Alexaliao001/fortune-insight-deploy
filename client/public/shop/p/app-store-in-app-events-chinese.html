Where zh-Hans In-App Events appear

When Apple surfaces your event, buyers on the China storefront see an event card — image or video, event name, short description, and badge — in places like the Today tab and Search. Tapping opens an event details page with the long description and larger portrait media.

  • Event card — landscape media (16:9), event name (up to 30 characters), short description (up to 50 characters)
  • Event details page — portrait media (9:16), long description (up to 120 characters), deep link to in-app content
  • Product page — upcoming and live events listed chronologically; high-priority events can sort ahead of normal priority

Apple chooses whether and where to feature any given event. Complete zh-Hans metadata improves locale fit when your event is shown — it does not force placement or impressions.

Apple Connect field limits (In-App Event text)

Per Apple's In-App Events documentation, localized text fields are capped as follows. CJK characters count toward the same limits as Latin letters — plan shorter Chinese phrasing than English drafts.

  • Reference name — up to 64 characters; internal to Connect only, not visible on the App Store
  • Event name — up to 30 characters; appears on the event card and details page. Apple recommends a distinctive event title in title case (e.g. a named season or challenge), not a generic call to action
  • Short description — up to 50 characters; summarizes the event on the card. Apple recommends sentence case
  • Long description — up to 120 characters; extra context on the details page (rewards, participation notes). Apple recommends sentence case

Event card media and event details page media are separate image or video uploads with fixed aspect ratios — not text fields. If your English event artwork has embedded headline text, translating that requires redesigning the asset; AppLocale delivers Connect text only.

Common mistakes on China-targeted In-App Events

  • English event copy on a zh-Hans listing — the product page reads native; the event card still shows Latin script fallback
  • Machine-translated event names — 30 characters of formal 翻译腔 that does not match your listing tone or game genre vocabulary
  • Generic English titles reused verbatim — "Live Stream Event" or "Limited Time Offer" instead of a named event Apple can distinguish on the card
  • Long description stuffed with keywords — the 120-character slot is for participation context, not ASO keyword packing from your main description
  • Assuming one zh-Hans paste covers all events — each event needs its own localization row; copying event A's text into event B reads wrong when rewards or dates differ
  • Mismatched listing promise — event short description advertises a feature your zh-Hans description never mentions, or uses payment vocabulary inconsistent with your IAP copy
  • Untranslated text in event artwork — Connect text is Chinese but the 16:9 card image still shows English headlines (a design fix, not a metadata paste)

Better zh-Hans event metadata reduces friction when users tap Open — it does not replace in-app localization, deep link testing, or Apple's editorial choices about featuring.

What good zh-Hans In-App Event copy looks like

Apple's guidance favors specific event names and accurate summaries. For China storefront events, align tone with your existing zh-Hans listing:

  • Event name (30 chars) — name the season, challenge, or collab: "夏日排行榜挑战" not "精彩活动等你来"
  • Short description (50 chars) — one crisp outcome: who can join, what happens, any time window — within the character cap
  • Long description (120 chars) — rewards, eligibility, or subscription note if participation costs extra — mirror vocabulary from your IAP localization when relevant
  • Voice match — casual game vs professional tool; same 你/您 and punctuation habits as your description field
  • Schedule honesty — dates and times are set in Connect, not in copy; do not promise "starts tomorrow" in text if publish dates differ by storefront

Do In-App Events use the same copy as my default App Store listing?

No. Each In-App Event has its own localized metadata in App Store Connect — event name, short description, and long description — separate from your default listing's title, subtitle, description, and keywords. A complete zh-Hans listing row does not auto-fill In-App Event fields.

What are Apple's character limits for In-App Event text fields?

Per Apple's App Store Connect documentation: event name up to 30 characters, short description up to 50 characters (shown on the event card), and long description up to 120 characters (shown on the event details page). Reference name (internal only) is up to 64 characters. Limits apply per localization.
