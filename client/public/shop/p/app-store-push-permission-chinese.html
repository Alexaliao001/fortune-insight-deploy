Push engineering vs zh-Hans listing copy — two different jobs

Teams assume notification capability covers storefront language. Xcode, Developer portal, and Connect actually separate push behavior from product-page copy:

  • Push Notifications capability — toggled in Xcode and linked to your App ID. Controls whether the app can register for remote notifications. Does not generate Chinese listing text.
  • APNs certificates & server payloads — configured in Apple Developer and your backend. Separate from the zh-Hans description paragraph that explains alert value to buyers.
  • UNUserNotificationCenter & permission prompts — in-app code and Info.plist usage strings. Your listing may mention alerts; implementing notification handlers is engineering work, not listing copy.
  • Pricing and Availability → China — makes the app downloadable on the China App Store. Separate from language rows.
  • App Store tab → Chinese (Simplified) localization — independent row for title, subtitle, keywords, description, promotional text, screenshots, and caption lines. Empty or English here means China buyers see English fallback regardless of push capability flags.

Working push alerts in the binary and a localized China listing are both required when you sell on the China storefront — neither replaces the other.

Push-notification–specific listing copy — what translates differently

Alert-centric listings use vocabulary general utility guides rarely cover. zh-Hans copy should reflect how Chinese App Store readers describe notification opt-in — not a literal paste of US marketing:

Stay Notified and Allow Notifications phrasing

US pages use "Stay Notified", "Enable push notifications", or "Allow Notifications" on onboarding mockups. Chinese buyers expect concise 开启通知, 及时接收提醒, or 消息推送 phrasing rather than English slogans left on screenshot overlays.

Alert types without over-claiming

Description and caption lines should name the alert categories your app actually sends — order status, price drops, habit reminders, social mentions — without promising instant delivery, guaranteed frequency, or features your backend does not support. Common mistakes on push-notification zh-Hans listings

  • Assuming APNs setup localizes automatically — push capability enabled in Xcode; zh-Hans row never added or left blank
  • Only translating the description — subtitle, keywords, and Stay Notified screenshot caption lines still English
  • Calling push alerts "messages" vaguely — 消息 alone is ambiguous; specify 推送提醒 or the alert category buyers care about
  • Promising alerts the app does not send — listing claims real-time price tracking when notifications are daily digests only
  • Conflating listing copy with permission prompt strings — NSUserNotificationUsageDescription and in-app pre-prompt UI are binary localization, not Connect metadata
  • English Allow Notifications on zh-Hans screenshots — Connect caption fields are Chinese but burned-in permission mockups on PNG exports are still Latin
  • What's New still English after push launch — see What's New in Simplified Chinese when notification features shipped in a recent version
  • Expecting AppLocale to configure APNs — certificates, entitlements, and server payload work are outside listing rewrite
